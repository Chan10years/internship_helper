# 低年级暑期实习助手 UI 改版设计

> 归档说明：本文是 2026-06-24 UI 改版的历史设计规格，用于理解当时的实现背景。当前 Web UI 权威规范以 `docs/06_WEB_UI_SPEC.md` 为准。

## 1. 目标与定位

本次改版将现有本地岗位浏览页升级为一个面向低年级学生、零经验求职者和第一次寻找暑期实习用户的小型产品。

产品预计可供不超过 1000 人使用，但本阶段仍沿用当前本地数据与静态前端架构，不引入账号、数据库、在线爬取入口或多用户后端。

页面的单一核心任务是：

> 让第一次找实习的人愿意开始探索，并能高效找到、比较和查看真实岗位。

品牌主张为：

> 不用准备好，先去看看。

视觉气质不是成熟职业平台，也不是传统招聘后台，而是一部关于“第一次从校园走向城市”的夏日成长电影。

## 2. 设计原则

1. 首屏负责让用户产生探索欲，岗位浏览区负责效率。
2. 青春感来自真实场景、自然光、人物状态和节奏，不来自糖果配色或幼态组件。
3. 高级感来自影像、字体尺度、留白、构图和克制动效，不来自玻璃拟态、渐变光晕或堆叠阴影。
4. 不制造“大平台”幻觉，岗位数量、来源和评分状态均按真实数据展示。
5. 关键岗位信息始终可扫描，不因视觉表达而隐藏。
6. 现有搜索、筛选、排序、详情和原链接能力必须完整保留。

## 3. 视觉参考与原创边界

参考方向来自 SiteInspire 中的 Big Type、Typographic、Fashion、Unusual Layout 和 Use of Animation 类作品，以及用户提供的 Coutumes 等页面截图。

借鉴的是以下设计语言：

- 大幅影像作为页面情绪主体。
- 超大标题与小号信息形成尺度反差。
- 编辑型网格和不对称构图。
- 文字与画面发生裁切、遮挡和层叠关系。
- 动效集中在少数关键转场。

不复制任何参考网站的品牌、版式细节、文案、素材或完整交互。

## 4. 页面结构

### 4.1 电影式首屏

首屏占据主要视口，使用一张本地电影感影像作为视觉主体。

内容包括：

- 小型品牌标识：`INTERNSHIP`。
- 主标题：`不用准备好，先去看看。`
- 辅助信息：真实岗位总数、数据来源和最近更新时间。
- 主操作：`开始找实习`。
- 次操作：`打开筛选`。

主标题采用超大尺寸并允许部分裁出视口边界。首屏不展示传统筛选工具栏或卡片统计区。

### 4.2 岗位浏览区

桌面端采用编辑型双栏：

- 左侧为可滚动岗位目录，承担快速扫描和选择。
- 右侧为当前岗位的“大幅封面”，展示岗位标题、公司、城市、薪资、来源和匹配分。

目录不是独立圆角卡片集合，而是由细分隔线、文字层级和大面积留白组织的杂志目录。

切换岗位时，右侧封面内容更新；默认选中筛选结果中的第一条岗位。

### 4.3 搜索与筛选

搜索和筛选放入从右侧滑入的全高抽屉，避免长期占用视觉空间。

抽屉保留：

- 关键词搜索。
- 城市筛选。
- 来源筛选。
- 公司筛选。
- 标签筛选。
- 按匹配分排序。
- 清除全部条件。
- 当前结果数量。

关闭抽屉后，页面顶部保留一个紧凑的筛选摘要，例如：

`深圳 / 实习僧 / 12 个结果`

### 4.4 岗位详情

点击当前岗位的“查看完整岗位”后，以全屏杂志内页展开，不跳转路由。

详情页包括：

- 岗位、公司、城市、薪资、实习时长、学历和每周到岗天数。
- 来源和采集时间。
- 岗位描述。
- 标签。
- 匹配分与匹配原因。
- 简历建议。
- 原岗位链接。

影像封面之后使用稳定的“编辑部档案”结构：

- 顶部横向事实栏集中展示薪资、周期、学历、到岗、匹配分和采集时间。
- 正文左侧为单一阅读主栏，仅承载完整岗位描述，控制行长和字号，避免多块长文互相争抢空间。
- 右侧为紧凑摘要栏，依次展示匹配分、匹配理由、简历准备建议和原岗位入口。
- 摘要栏在桌面端可随阅读吸附；移动端回到正文之后顺序排列。
- 不使用跨行拼贴网格，不让内容长度差异制造大面积空洞。

详情页支持关闭按钮、点击遮罩关闭和 `Esc` 关闭。原岗位链接仅在链接为安全 HTTP/HTTPS 地址时展示。

### 4.5 移动端

移动端改为纵向电影海报流：

- 首屏保留大字和影像。
- 岗位目录与封面合并为连续海报条目。
- 筛选使用全屏抽屉。
- 岗位详情使用全屏纵向阅读层。

移动端不强行保留桌面双栏结构。

## 5. 影像方向

### 5.1 内容

影像围绕“校园到城市的第一次过渡”：

- 宿舍、图书馆、教学楼和校园出口。
- 公交或地铁窗边、天桥、街道和城市清晨。
- 背包、电脑、耳机、作品草稿和手写笔记。
- 结伴出发、独自观察、边走边看和初到陌生空间。
- 轻量创作现场，而非正式会议或商务演示。

### 5.2 质感

- 夏日自然光。
- 轻微胶片颗粒。
- 真实抓拍或电影静帧感。
- 人物有动作和情绪，但不直视镜头摆拍。
- 构图允许局部遮挡、运动模糊和不完美瞬间。

### 5.3 明确排除

- 商务西装和成熟精英形象。
- 会议室握手、团队围桌微笑等图库场景。
- 夸张科技屏幕和虚构数据。
- 过度梦幻、二次元或廉价青春校园宣传片质感。
- 可识别的真实公司 Logo、学校 Logo 或私人信息。

### 5.4 素材策略

本阶段使用 3 至 4 张本地优化影像：

- 一张首屏主视觉。
- 两至三张用于岗位浏览区的轮换背景。

图片保存为 WebP，并提供 JPEG 回退或兼容格式。前端不依赖外部图片地址。

岗位不会逐条生成专属图片。右侧封面按岗位信息稳定映射到有限的本地影像与强调色，以控制资源规模和加载成本。

## 6. 视觉系统

### 6.1 色彩

- 电影黑：`#11110F`
- 纸张白：`#F2F0E9`
- 柔和灰：`#C8C5BC`
- 墨灰：`#34332F`
- 主强调色：芥末黄 `#E9B52B`
- 备用强调色：信号橙 `#E85A2A`

同一屏幕只使用一种强调色。强调色用于标题、选中状态、分隔标记和关键操作，不用于大面积组件填充。

### 6.2 字体

- 巨幅标题和数字：`Impact, Haettenschweiler, "Arial Narrow Bold", sans-serif`
- 中文标题和正文：`"Microsoft YaHei UI", "PingFang SC", "Noto Sans CJK SC", sans-serif`
- 元数据和标签：使用正文栈的小号大写或加宽字距样式。

中文巨幅标题通过独立容器与水平压缩控制形成海报比例，不对正文使用变形。

### 6.3 字号层级

- 首屏主标题：桌面端 `clamp(72px, 12vw, 190px)`。
- 当前岗位标题：桌面端 `clamp(54px, 8vw, 128px)`。
- 岗位目录标题：`20px–30px`。
- 正文：`16px–18px`。
- 元数据：`11px–13px`。

### 6.4 形状与分隔

- 默认不使用圆角卡片。
- 抽屉和详情层可以使用极小圆角或直角。
- 主要结构使用细线、裁切边界、留白和文字对齐完成。
- 按钮以文字、下划线、反色块或细边框表达，不使用胶囊按钮套装。

## 7. 标志性视觉

页面的唯一主要视觉签名是：

> 岗位标题像电影片名一样覆盖在大幅影像上，并在视口边缘被有意识地裁切。

这个元素同时用于首屏主张和当前岗位封面，形成统一记忆。

其他区域保持克制，避免再加入贴纸、光球、装饰图标或多套视觉噱头。

## 8. 动效

### 8.1 首屏

- 页面进入时影像由 `scale(1.04)` 缓慢回落至 `scale(1)`。
- 主标题分行错时上移出现。
- 元数据和操作在标题之后淡入。

### 8.2 岗位切换

- 旧岗位标题向上裁切离场。
- 新标题从下方进入。
- 背景影像做轻微位移或交叉淡化。
- 匹配分数字使用短暂计数或翻页式切换。

### 8.3 滚动

- 首屏到岗位浏览区只设计一次明确转场。
- 不为每个普通元素添加滚动动画。
- 岗位目录悬停只改变文字反色、细线长度或封面微位移。

### 8.4 可访问性与性能

- 遵守 `prefers-reduced-motion`。
- 减少动态效果时取消视差、缩放和错时动画，仅保留即时淡入。
- 动画优先使用 `transform` 和 `opacity`。
- 不加入自动播放音频。
- 不依赖持续高频 JavaScript 动画循环。

## 9. 交互状态

### 9.1 初始状态

- 加载完成后显示真实岗位总数。
- 自动选中第一条可见岗位。
- 如果无岗位，首屏仍存在，浏览区显示明确的空状态。

### 9.2 筛选无结果

显示：

`这组条件暂时没有岗位。`

并提供：

- `清除筛选`
- 当前启用条件摘要

### 9.3 数据加载失败

显示：

`岗位数据没有加载成功。请刷新页面后再试。`

页面视觉框架保留，不显示虚构示例岗位。

### 9.4 未评分岗位

- 显示 `未评分`，不使用 `0`。
- 排序时仍保持未评分岗位在已评分岗位之后。

### 9.5 键盘操作

- 岗位目录项可通过 `Tab` 聚焦。
- `Enter` 或空格选择岗位。
- 抽屉和详情打开时焦点进入对应区域。
- `Esc` 关闭抽屉或详情。
- 关闭后焦点返回触发按钮。
- 所有交互元素具有清晰的可见焦点状态。

## 10. 前端架构与职责

继续使用：

- `src/server/public/index.html`
- `src/server/public/style.css`
- `src/server/public/app.js`

不增加前端框架、构建工具或依赖。

JavaScript 内部按职责拆分为短函数：

- 数据加载与标准化。
- 筛选选项初始化。
- 搜索、筛选和排序。
- 岗位目录渲染。
- 当前岗位封面渲染。
- 详情渲染。
- 抽屉和详情层状态管理。
- 键盘与焦点管理。
- 安全链接校验。

服务器和数据接口保持不变。前端仍从 `/api/jobs` 读取岗位，不触发爬虫。

## 11. 数据流

1. 页面请求 `/api/jobs`。
2. 加载成功后保存原始岗位数组。
3. 生成城市、来源、公司和标签筛选选项。
4. 根据搜索、筛选和排序条件生成可见岗位数组。
5. 渲染岗位目录和结果数量。
6. 保留当前选中岗位；若已不在结果中，则选中新的第一条。
7. 当前岗位驱动右侧封面与详情内容。
8. 数据仅在 DOM 中以 `textContent` 等安全方式渲染，不直接插入不可信 HTML。

## 12. 实现边界

本次包含：

- HTML 语义结构改造。
- CSS 视觉系统、响应式布局和动效。
- 原生 JavaScript 交互完善。
- 3 至 4 张本地影像素材。
- 现有功能保留与可访问性增强。
- UI 自动化检查和桌面、移动端视觉检查。

本次不包含：

- 登录和用户账号。
- 数据库。
- 云端部署配置。
- 多用户同步。
- 收藏、投递状态或个人档案。
- UI 内启动爬虫。
- 为每个岗位生成独立图片。
- 后端扩容或千人并发承诺。

小规模上线能力属于后续独立阶段，应先明确部署方式、数据更新机制、隐私策略和访问负载。

## 13. 测试与验收

### 13.1 功能

- 能加载并显示现有岗位。
- 搜索范围仍覆盖岗位、公司、城市、描述、标签和原始文本。
- 城市、来源、公司和标签筛选有效。
- 匹配分排序正确，未评分岗位置后。
- 选择岗位后封面和详情同步更新。
- 原岗位链接仅对安全 HTTP/HTTPS 地址开放。
- 空状态和加载失败状态清楚。

### 13.2 可访问性

- 所有操作可通过键盘完成。
- 抽屉和详情层焦点行为正确。
- 焦点样式清晰。
- 文本与背景对比度可读。
- 减少动态效果设置有效。

### 13.3 响应式

- 桌面宽屏双栏布局完整。
- 中等宽度下文字不溢出，筛选抽屉可用。
- 手机端切换为纵向海报流。
- 超大标题裁切是有意构图，不遮挡关键操作。

### 13.4 性能

- 本地影像经过压缩。
- 首屏主图优先加载，其余图片延迟加载。
- 不使用无限动画循环或大型动画库。
- 页面在无网络字体和无外部图片服务时仍可完整使用。

### 13.5 项目检查

- 运行 `npm run check`。
- 使用桌面和手机视口检查真实页面。
- 复核 `docs/08_ACCEPTANCE_CHECKLIST.md` 的 Web UI 与 Safety 部分。
- 不执行 Git 修改命令。
- 不安装依赖。

## 14. 成功标准

改版成功需要同时满足：

1. 第一眼具有电影海报或时装编辑网站的视觉冲击，而非 SaaS 模板感。
2. 用户能明确感受到“第一次找暑期实习”的轻松、期待和成长感。
3. 岗位搜索、筛选、比较和详情阅读不比当前版本更困难。
4. 页面诚实呈现产品规模和真实数据，不模仿大型招聘平台话术。
5. 在原生 HTML、CSS 和 JavaScript 范围内稳定运行。
